# Правила работы над проектом «Сканирование HDD и создание Архива»

Этот файл Claude Code читает автоматически в начале КАЖДОЙ сессии в этой папке. Правила — от владельца, обязательны.

## Размер файлов (главное правило)
- Файл кода (`.py`, `.ps1` и любые другие) — **цель до 400 строк**.
- **С 500 строк** — уже задуматься о разнесении на две части и сделать это ДО того, как дописывать новое.
- **600 строк — предел, превышать нельзя.** Растёт файл — разбиваем на две части или выносим часть в файл, где строк меньше.
- Перед правкой файла проверь его длину. После правки — тоже. Файлы, уже превысившие предел (список долга `FILE_DEBT`
  в `catalog/test_modules.py` и в проверке других файлов), расти не могут — только уменьшаться.
- Правка дизайна или текста экрана должна затрагивать один небольшой файл (структура — `docs/СТРУКТУРА_ПРОГРАММЫ.md`).

## Как работаем
- Владелец не программист, Windows 10. Отвечать коротко, по-русски, без жаргона.
- Первым делом прочитать последний файл передачи `ПЕРЕДАЧА_СЕССИИ_*.md`, затем `ЖУРНАЛ_ДОДЕЛОК.md` и
  `docs/ПРАВИЛА_ЗАПИСИ_И_СБОРКИ.md` (разделы 4, 8, 12–14).
- Замечания владельца — сначала в `ЖУРНАЛ_ДОДЕЛОК.md`; при неясности — макет; код — после «да».
- **Критики — по ВСЕМ решениям** (устройство, дизайн, разбивка, готовый код): скилл «Критик», обе модели —
  `deepseek-v4-pro` и `gpt-6.1-sol`.
- Одно задание — одному свежему субагенту с коротким описанием (не тянуть одного субагента с длинной историей).
  Два субагента параллельно — только если не трогают одни и те же файлы.
- Тесты и коммит — в основном чате. Полный прогон — строка «Полный прогон тестов» в `docs/ПРАВИЛА_ЗАПИСИ_И_СБОРКИ.md`.
- На GitHub — только по слову владельца. Запись в настоящие данные (таблицы, база) — только после явного «да».
- Программа НИЧЕГО НЕ УДАЛЯЕТ. Перемещения — только в пределах одного диска. Служебные папки «Скопировано на …»
  владелец удаляет сам и подтверждает в программе.
- Секреты не читать и не выводить (`C:\secrets\.env` и любые `.env`).
- Отчитываться фактами и числами; не выдавать частичный результат за выполнение задачи.
