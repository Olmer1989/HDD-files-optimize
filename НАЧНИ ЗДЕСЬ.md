# Начни здесь: вход в проект для новой сессии или другой нейросети

Состояние на **12.11.2026, вечер**. Этот файл — единственная точка входа. Сначала он,
потом документы, на которые он ссылается. Если что-то здесь расходится с другими
документами — верить журналу операций и спросить пользователя.

## 1. Что мы делаем

Пользователь (не программист) сводит семейный фото- и видеоархив с ~56 старых носителей
на два больших диска и раскладывает остальное по тематическим дискам.

- **Диск 45-16тб** (HDD45, обычно G:) — семейный архив, копия 1.
- **Диск 77-14тб** (HDD77, обычно S:) — семейный архив, копия 2.
- Фильмы, оцифровки кассет, «Север и Работа», «Саша, Таня…» — на отдельные диски.

Каждый носитель заранее описан сканером: список всех файлов и **SHA-256 фото и видео**.
Вся работа строится на этих описях, а не на чтении дисков.

## 2. Роли

- **Нейросеть**: считает по описям, что есть и чего не хватает; готовит списки; ведёт
  журнал и документацию. Системные команды (diskpart, chkdsk, mountvol) — только с
  объяснением последствий и только по решению пользователя.
- **Пользователь**: подключает диски, сам запускает копирование, **сам удаляет файлы**,
  принимает все решения «нужно / не нужно».
- Отвечать ему коротко и по-русски, таблицы — «папка — сколько — куда».

## 3. Типовой запрос: «подключил диск — чего с него не хватает на 45 и 77»

Диски для ответа не нужны, считается за секунды из папки проекта:

```powershell
py catalog\disk_vs_45_77.py HDD17                 # таблица по папкам верхнего уровня
py catalog\disk_vs_45_77.py HDD17 --depth 2 --everywhere   # глубже + «больше нигде»
py catalog\disk_vs_45_77.py HDD17 --list          # Excel: каждый файл, которого нет ни на 45, ни на 77
```

Номер диска (HDDxx) пользователь называет сам или он определяется по серийному номеру
тома: реестр — `РЕЗУЛЬТАТЫ СКАНИРОВАНИЯ - сводные\` (папка на носитель, «Реестр дисков»).
Буквы дисков меняются, в документах и списках всегда номер.

**Обязательная поправка.** `disk_vs_45_77.py` смотрит только в описи, сделанные
08–10.11.2026. Всё, что с тех пор скопировано, перемещено и удалено, в описях не
отражено. Перед ответом прочитать [`docs/ЖУРНАЛ_ОПЕРАЦИЙ.md`](docs/ЖУРНАЛ_ОПЕРАЦИЙ.md) и
журналы скриптов `Каталог дисков\<задача>\Журнал копирования *.tsv` и учесть их:
скопированное с A на B числится и на B, удалённое — нигде. Автоматического учёта пока
нет (раздел 8).

## 4. Копирование: только единым шаблоном

**Новые скрипты копирования не пишутся** (решение пользователя 12.11.2026).

- Отлаженный скрипт: [`Каталог дисков/_ШАБЛОН копирования/Копировать.ps1`](Каталог%20дисков/_ШАБЛОН%20копирования/Копировать.ps1)
  (версия 2.1) и [`Запустить.cmd`](Каталог%20дисков/_ШАБЛОН%20копирования/Запустить.cmd).
  Копирует файлы **любого размера** (ошибка с файлами больше 2 ГБ была в старых
  скриптах, здесь её нет), считает SHA-256 прочитанного и сверяет с описью, ничего не
  удаляет и не перезаписывает, останавливается по Q, прекращает работу, если диск завис.
- Под задачу создаётся папка `Каталог дисков\<задача>\`, туда **без правок** копируются
  эти два файла и кладутся два файла данных (UTF-8, поля через TAB):
  - `тома.tsv` — `<имя диска> TAB <серийный номер тома> [TAB <папка на этом диске>]`;
    первая строка — источник, остальные — цели. Без третьей колонки файлы идут в
    `ПЕРЕНОС с других дисков\<имя источника>\<тот же путь>`. Если диска-цели нет под
    рукой, в его строке указывают серийный номер другого диска и папку на нём.
  - `список.tsv` — `<цель> TAB <путь от корня источника> TAB <размер> TAB <пометка> TAB <SHA-256 из описи>`.
- Списки строят генераторы `catalog\make_copy_*.py` (образцы: `make_copy_k_to_45_77.py`,
  `make_copy_j_missing.py`). Для нового диска — новый набор в генераторе, а не новый скрипт.
- Пользователь запускает двойным щелчком по `Запустить.cmd`, отвечает «да».
- После запуска: разобрать журнал скрипта (сколько скопировано, ошибки, «нет источника»),
  дописать итог в журнал операций.
- Если шаблону чего-то не хватает — меняется сам шаблон: новая версия в первой строке,
  тест в Windows PowerShell 5.1 через `-TestRoots` на наборе с файлом больше 2 ГБ, запись
  в документации. Подробно — раздел 3.6
  [документации проекта](Источники%20информации/Документация%20проекта%20—%20оптимизация%20семейного%20фото-%20и%20видеоархива.md).

Копирование на новые тематические диски («Оцифровки», «Фильмы» и т. п.) делается тем же
шаблоном: диск получает имя, его строка добавляется в `тома.tsv`, список строится по
разделу.

## 5. Куда что класть

- Действующее правило: на 45 и 77 всё новое кладётся в
  `ПЕРЕНОС с других дисков\<номер источника>\<тот же путь>`, раскладка по годам и
  событиям — отдельным этапом позже. На 77 есть и вторая папка, созданная пользователем:
  `ПЕРЕНОС с других дисков на диск 77` (туда 12.11 пошёл HDD17).
- **Разделы архива, как их видит пользователь** (туризм и рафтинг; Сафари и Север; Саша,
  Таня, Наташа; фильмы; оцифрованные источники; JPEG; RAW; путешествия; другое) —
  [`docs/ПЛАН_РАЗМЕЩЕНИЯ.md`](docs/ПЛАН_РАЗМЕЩЕНИЯ.md), раздел 1б. Там же роли физических
  дисков (разделы 1 и 3). Эти две схемы между собой ещё не согласованы — уточнять у
  пользователя, прежде чем раскладывать по тематическим дискам.

## 6. Правила, которые нельзя нарушать

1. Ничего не удалять. Удаляет только пользователь, и только когда файл по SHA-256 есть и
   на 45, и на 77 (или он сам сказал «не нужно»).
2. «Тот же файл» — только совпадение SHA-256. Имя и размер ничего не доказывают.
3. Решения — по описям; диски лишний раз не читать и не перехешировать.
4. Любую операцию с файлами и любое решение пользователя — в
   [`docs/ЖУРНАЛ_ОПЕРАЦИЙ.md`](docs/ЖУРНАЛ_ОПЕРАЦИЙ.md) в тот же день.
5. О состоянии («запускалось / не запускалось», «скопировано / нет») говорить только
   после проверки журналов, а не по памяти.
6. При ошибках диска в журнале Windows (Ntfs, disk, UASPStor) — остановиться. Не
   продолжать работу через сбоящий бокс, не запускать `chkdsk /f` до копии данных.
7. Секреты — только в `C:\secrets\.env`, файл не читать; в коде — имена переменных.

Полный текст правил — [`docs/АЛГОРИТМ.md`](docs/АЛГОРИТМ.md) (большой; раздел 4.1 — порядок
переносов и правила скриптов, раздел 2 — что считается тем же файлом).
