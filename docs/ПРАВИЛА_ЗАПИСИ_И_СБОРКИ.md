# Правила записи и сборки базы (этап 0 программы с окном)

14.11.2026. Ответ на рецензию GPT к «Окно_программы_v1.md» (`Проверка Архитектуры сортировки файлов\`).
Здесь записано, как программа работает НА САМОМ ДЕЛЕ; каждое правило проверено автотестом (в скобках).
Окно, командная строка и нейросеть в чате обязаны соблюдать эти правила.

## 1. Как применяются дописанные таблицы

- Модуль — неизменяемый первоисточник. Строка `ручные операции.tsv` и строка `исключения.tsv` — отдельные
  модули (ключ — номер строки, контрольная сумма — её текст). Журнал скрипта — модуль, который можно дописывать.
- Таблица `applied` в базе помнит каждый учтённый модуль. При любой команде сборщик сравнивает модули на диске
  с `applied` и применяет только новые: новую строку таблицы, новые строки журнала (`IncrementalTest`).
- Учитываются только **целые строки** (с переводом строки в конце). Строка, которую ещё пишут, ждёт
  (`test_unfinished_row_is_not_applied_and_blocks_writing`, журнал — `test_steps_equal_full_rebuild`).
- Изменилась или пропала уже учтённая строка или журнал — сборщик не чинит базу по частям: сообщает и собирает
  её заново целиком (`test_changed_module_forces_full_rebuild`).
- Решения (`решения.tsv`) в базу не применяются: они читаются при каждом ответе.

## 2. Единый путь записи

- Таблицы владельца пишет **только** пакет `catalog\service\` (бывший `service.py`; замок и дописывание — `service\write.py`): из окна, из командной строки и из чата — через
  команды `hashbase.py manual`, `decide`, `exclude`, `fix-manual`. Без `--yes` команда только показывает
  предпросмотр. Нейросеть в чате таблицы вручную не дописывает.
- Перед записью сервис проверяет: действие и дата в верном виде; диск есть в базе; по пути в базе есть файлы
  (иначе — отказ: защита от опечатки); такой же строки ещё нет (повторное нажатие не создаёт вторую операцию,
  `test_repeat_is_refused`); последняя строка таблицы закончена.
- Путь — это сам файл или всё внутри папки: «Фото» не задевает «Фотоархив» (`test_neighbour_names_are_not_touched`).
- **Пробелы в путях не обрезаются нигде (этап 16, 16.11.2026).** Имя папки может начинаться или кончаться пробелом
  (« Перемещение перед Индонезией - временное» на HDD51): по краям пути убираются только разделители «\»
  (`hb_core.util.clean_path`). Поля таблиц владельца читаются `row_fields`: диск, действие, решение, дата — без
  пробелов по краям, путь — как в файле. Так же — окно («Я сделал в Проводнике», «Команды», фильтры «Списка
  файлов»), приём частичного скана, сканер (1.6.1), шаблон копирования (2.6, папка цели в `тома.tsv`). Папки « X»,
  «X » и «X» — три разные папки (`SpacesTest`). На настоящих таблицах полей с пробелом по краям не было (проверено
  чтением) — пересборки не требуется.
- Запись идёт под замком `_БАЗА\таблицы.lock`: два писателя не портят строки друг друга
  (`test_concurrent_writers`). Перед записью копия таблицы кладётся в `_БАЗА\архив таблиц` (последние 200).
- Строка дописывается целиком одной записью на диск, затем сразу применяется к базе. Если программа упала
  между записью и применением, строка уже является модулем: следующая команда применит её один раз
  (`test_saved_but_not_applied_is_applied_once_later`).

## 3. Применение к базе и пересборка

- Применение новых модулей и запись в `applied` — одна транзакция SQLite: при сбое не применяется ничего,
  следующая команда начнёт заново. Одна сборка за раз — замок `_БАЗА\сборка.lock`.
- Полная пересборка (`rebuild` или автоматическая) пишет новую базу во временный файл; рабочая база остаётся
  на месте до последнего шага — замены файла. Ошибка при подготовке оставляет рабочую базу. Для замены все
  программы должны закрыть свои соединения с базой: окно закрывает их, увидев занятый замок сборки, и
  открывает снова после неё; результат запроса, начатого до пересборки, на экран не выводится (поколение базы —
  время сборки в таблице `meta`).
- Самопроверка `rebuild`: база с нуля сверяется с базой, собранной по шагам, по контрольным суммам всех таблиц.

## 4. Что значит «копия подтверждена»

Степень подтверждения каждой записи «файл лежит на носителе»:

| Степень | Основание | Копия? |
|---|---|---|
| S | SHA-256 посчитан сканером по самому файлу (полная опись или частичный скан) | да |
| C | файл скопирован единым шаблоном; SHA-256 прочитанных байтов в журнале. Или (шаблон 2.5) в цели уже лежал файл того же размера, шаблон его прочитал, и SHA-256 совпал с описью (без хеша в описи — с прочитанным источником): строка «уже есть, SHA-256 совпал…» с хешем | да |
| Z | шаблон сверил только размер или увидел «уже есть» (без сверки — шаблоны до 2.5, старые журналы) | нет |
| U | со слов владельца (Проводник) | нет |
| X | файл изменился после подсчёта хеша | нет |
| N | хеш не считался (не фото и не видео) | — |

- **Шаблон 2.7 (17.11.2026, проблемные файлы, решение владельца).** Все обращения к файлам — через `\\?\` (сетевые —
  `\\?\UNC\`), в журнале и на экране пути обычные; путь списка без пустых частей, «.», «..» и «X:». Причина ошибки в
  журнале (строка по-прежнему «ОШИБКА: …» — окно, «Повторить копирование» и mvlist не менялись): «файл занят другой
  программой — закройте её и нажмите «Повторить копирование»»; «нет прав на чтение … — программа права не меняет:
  Свойства — Безопасность — Дополнительно — Владелец, или запуск от имени администратора»; «сбойный сектор или ошибка
  ввода-вывода … (код Windows N)»; «в имени запрещённый в Windows символ …». В «5 ошибок подряд» не считаются «занят» и
  «нет прав» на источнике и запрещённое имя; сбойные сектора считаются. Имена с точкой или пробелом на конце и
  зарезервированные (CON, PRN, AUX, NUL, COM/LPT) копируются под заменой (концевые «.» и « » → «_», `CON.jpg` →
  `CON_.jpg`), запись «скопирован… (имя изменено: «…» -> «…»)»; «куда» — новый путь (по нему степень C и перемещение);
  замена всегда одинаковая, занятое в цели имя — КОНФЛИКТ. Символы `< > : " | ? *` и управляющие Windows не открывает —
  только «ОШИБКА» и список. Не скопированные файлы в «Скопировано на …» не попадают и выводятся списком «Проблемные
  файлы <дата время>.txt» рядом с журналом. Прежняя версия — `Копировать - версия 2.6.ps1.txt`. Уточнения по критикам: заменённое имя, совпавшее с другим путём задания, не
  копируется (ОШИБКА, чтобы два файла не слились); уже лежащая копия под заменённым именем признаётся только по журналу
  этого же задания, иначе КОНФЛИКТ; любое двоеточие в строке списка — проблема одной строки; папка на месте будущего
  файла — КОНФЛИКТ; в «Проблемных файлах» — строки «не обработано: N — причина» после остановки. Тесты —
  `catalog/test_problem_files.py`.
- **Шаблон 2.6 (16.11.2026, этап 16, решение владельца): свободное место** проверяется только под файлы, которых на
  месте назначения ещё нет. Строка, у которой в цели уже лежит файл, места не займёт: того же размера — «уже есть»
  (сверка SHA-256, 2.5), другого — КОНФЛИКТ (ничего не пишется). Папки назначения перечисляются по одному разу (имя →
  размер, без учёта регистра; содержимое не читается); папку прочитать не удалось — её строки считаются новыми
  (места нужно больше, а не меньше). Запас — 1 ГБ, как раньше; нет места — «не хватает места», код 5, ничего не
  начато. Остальное как в 2.5 (степени, журнал, коды выхода, `-Confirmed -Expect`). Задание хранит свою копию шаблона:
  подготовленные с 2.5 так и работают. Прежняя версия — `Копировать - версия 2.5.ps1.txt`. Окно (`service.capacity`)
  по-прежнему считает недостающее по SHA-256 (часть Б). Тесты — `Template26` в `test_copy_template_review.py`.
- Шаблон 2.5 (16.11.2026, этап 15 логики v3): тот же размер, другой SHA-256 — «КОНФЛИКТ: на месте назначения другой
  файл того же размера (SHA-256 отличается)», в базу не идёт (как любой конфликт); простое «уже есть» 2.5 не пишет.
  Строки журнала разбирает `consts.copy_ok` / `HAVE_SHA` (сборка, `copied_from`, повтор задания, перенос `mvlist`).
- Запись носит происхождение (`origin`: опись, частичный скан, журнал, строка ручных операций) и время
  модуля. Журнал или ручная операция старше описи этого места не действуют.
- Перемещение на источнике (`mvlist`) — только если в месте назначения есть запись S или C с тем же SHA-256 на
  всех дисках, куда файл копировали или собирались копировать; шаблон перед перемещением ещё раз сверяет размер и
  дату файла. Подробно, для любых дисков-целей, — раздел 12.
- Это сведения базы, а не повторное чтение дисков: если владелец удалил копию и не записал этого, база не
  знает. Поэтому окно показывает основание и дату, а `candel` («можно ли удалять») отвечает «ДА» только при
  подтверждённых копиях на 45 и 77, полной описи и отсутствии предупреждений; иначе — «НЕДОСТАТОЧНО».

## 5. Ручная операция — сообщение владельца

- Записывается со степенью U (копия «со слов» никогда не считается подтверждённой); перемещение внутри
  одного диска сохраняет хеш и степень.
- Источник выбирается из каталога базы, в том числе на отключённом диске.
- Ошибочная строка исправляется командой `fix-manual`: строка заменяется, в комментарий пишется причина и
  прежнее содержание, копия таблицы — в архиве, база собирается заново (`test_mistaken_row_is_fixed_with_reason`).

## 9. Как окно запускает команды (раздел «Команды», 15.11.2026)

Код — `catalog/commands_page.py`; спор с GPT — `Проверка Архитектуры сортировки файлов\Окно_программы_v2_этап1.md`.
- **Описание.** Окно берёт у `hb_cli` только `commands()` — то же описание argparse, что у командной строки, и строит
  форму сама. Новая команда в `hb_cmd` появляется в окне без правки окна. Поле по имени аргумента: `disk*`, `--disk`,
  `disk2` — список носителей из базы; `--to` — галочки (по умолчанию 45 и 77); `folder*`, `path*`, `--source-folder`,
  `--folder` (несколько) — поле и «Выбрать…» по дереву базы; флажки — галочки с текстом help; `choices` — список;
  `date` — сегодня. Значение по умолчанию не передаётся. Перед запуском — проверка обязательных полей и разбор тем же
  argparse. Аргументы другого вида (`count`, `store_false` …) окно не заполняет: команда — только из командной строки.
- **Скрытие.** `GUI = False` (или dict имя → bool) в файле команды — в окне её нет, в командной строке есть. Сейчас
  скрыты `recovery-plan`, `recovery-staging` (восстановление — ручной режим владельца) и `family-plan`, `family-check`
  (разовые для HDD51). Проверяет `test_modules.py`.
- **Запуск.** Отдельный процесс: `python.exe` (рядом с `pythonw.exe` окна) `-X utf8 -u catalog\hashbase.py <аргументы>`,
  без консольного окна (`CREATE_NO_WINDOW`). Окно передаёт `HB_ROOT`, `HB_SCAN_ROOTS` (свои корни: в работе — обычные,
  в тестах — временные; читает их `hb_core/paths.py`) и `HB_FULL_OUTPUT=1` (`hb_cli` не сокращает ответ до 20 строк).
  Вывод виден по ходу; весь — в `_БАЗА\ответы\окно - последний вывод.txt`. Код выхода ≠ 0 — красным.
- **Запись.** Команда с `--yes` в описании — команда записи: «Выполнить» всегда без `--yes` (предпросмотр); после
  успешного предпросмотра «Записать» спрашивает и повторяет те же аргументы с `--yes`. Правка формы и сама запись
  гасят «Записать»: следующая запись — только после нового предпросмотра. После записи окно применяет новые модули.
- **Замки.** Сборка базы и запись таблиц защищены файловыми замками (`сборка.lock`, `таблицы.lock`) между всеми
  процессами: окно, его подпроцессы, консоль. При записи сервис под замком повторяет все проверки предпросмотра.
- **Остановка.** «Остановить» есть только у читающих команд (обрыв безопасен: полная сборка пишет во временный файл,
  частичная — одна транзакция; замок снимает ОС). Запись с `--yes` и создание задания (`mklist`/`mvlist` без `--dry`)
  не обрываются; закрыть окно во время них нельзя. После созданного этим запуском задания окно предлагает «Задания».

## 10. Пересканирование выбранных папок: когда прежнему хешу доверяем (15.11.2026)

Код — `scanner/rescan.py` (`decide`), сканер 1.4.0 `start --folder`; спор с GPT — `Проверка Архитектуры сортировки
файлов\Пересканирование_папок_v1.md`. Тесты — `scanner/test_rescan.py`, `catalog/test_rescan_folders.py`.

**Прежний хеш берётся без чтения файла, только если всё сразу:**
1. Прежняя запись — измерение сканера (`verified`) в последней полной описи носителя или в более новом частичном скане;
   для пути действует самый свежий источник, чья область его покрывает. Записи C, U, Z, X, N и рабочая база
   (`хеши.sqlite`) источником **не бывают**: такие файлы читаются.
2. Совпали путь, размер, mtime (до 100 нс), номер файла NTFS и время создания; строка хешей прежнего задания
   совпадает с его описью.
3. ChangeTime NTFS (время изменения записи файла; меняется при любой записи, переименовании, смене атрибутов)
   **раньше** момента, до которого прежний хеш заведомо не был посчитан: начала задания (или запуска), которое
   действительно прочитало файл. По цепочке «скан → пересканирование → ещё раз» граница остаётся исходной.
4. Том NTFS с тем же серийным номером, что в полной описи; даты не в будущем. Во время проверки файл открыт так,
   что писать в него нельзя; занятый файл читается.

Иначе файл читается заново. Переименованный файл хеш не наследует (помечается «возможно переименован»).
`--rehash-all` (галочка «Перечитать всё») — читать всё.

**Что это гарантирует:** защиту от обычных изменений файлов через Windows при верных часах компьютера. Не защищает от
умышленной подмены (ChangeTime можно выставить программно) и от тихой порчи носителя — это только `--rehash-all`.

**Степень в базе.** Взятый хеш остаётся S: это то же измерение сканером, что база уже учитывала из полной описи
(«измерено сканером при прежнем скане»); пересканирование лишь подтверждает, что метаданные не менялись. Откуда каждый
хеш и дата измерения — в `hashes.sqlite`, таблица `hash_info` (`how` = read / reused / own, `from_job`, `bound_ns`), и в
`result.json` / `runs.jsonl` (`reused_files`, `reuse_sources`, `reuse_basis`, `read_reasons`). Происхождение строки в
базе (`origin`) — частичный скан. Правило удаления (`candel`) не менялось: только S или C на 45 и 77.

**Приём.** Формат — как у сканов 13–14.11 (`scan_scope: partial`, `folders`, `hash_scope: all_regular_files`); логика
базы не менялась. Если какая-то папка при описи не открылась — состояние `inventory_incomplete`, и база скан не
принимает (иначе недоступная папка выглядела бы пустой и её записи исчезли бы). Файл, который не прочитался, остаётся
в описи без хеша — N. Скан старше уже учтённых поправок вызывает полную пересборку в порядке времени (сборщик).

**Окно.** «Диски и папки» → одна или несколько папок подключённого диска (Ctrl) → «Пересканировать папку…» →
предпросмотр по оглавлению (файлы не читаются) → «Начать сканирование…» и подтверждение → сканер отдельным процессом
без консоли, ход и «Остановить» (файлы `_БАЗА\пересканирование\<диск> ход.json / стоп.txt / вывод.txt`) → окно
применяет новые модули и показывает итог приёма. Сама программа сканирование не начинает никогда. Предпросмотр из
командной строки: `py catalog\hashbase.py rescan-plan HDDxx --folder "папка"`.

## 11. Хеш у всех файлов; сравнение по хешу для всех классов (15.11.2026, BUILD_VERSION 7, сканер 1.5.0)

Спор с GPT — `Проверка Архитектуры сортировки файлов\Хеш_всех_файлов_v1.md`. Тесты — `catalog/test_hash_all.py`,
`scanner/test_rescan.py`.

**«По хешу или по имени» решает наличие хеша у обеих сторон, а не класс файла.** Так было и раньше (все запросы делятся
на `sha is not null` и `sha is null`; приём скана ставит S любому файлу с прочитанным хешем, журнал шаблона — C любому
скопированному). Новое — смешанный случай:
- У файла есть подтверждённый хеш (S/C), у второй стороны копии с этим хешем нет, но лежит файл с тем же именем и
  размером, у которого хеш **не считался** (ev = N): пометка «сравнение только по имени и размеру» (`query.candidates`).
  Строки Z/U/X сюда не входят (о них — `sha_exp`), строка S/C с другим хешем — другое содержимое. Итоги «нет на 45/77»
  и «больше нигде» не меняются: копией считается только подтверждённая.
- `candel`: файл с хешем, у которого на каждом недостающем главном диске есть такой файл без хеша, — «НЕДОСТАТОЧНО
  ПОДТВЕРЖДЕНИЙ» (как тот же файл без хеша), а не «НЕТ». Z/U/X — по-прежнему «НЕТ». «ДА» для папки с документами
  возможно, когда у всех её файлов (и документов) есть S/C с тем же SHA-256 на 45 и на 77 вне удаляемой папки.
- `cmp`: пара «хеш в A — без хеша в B» с тем же именем и размером сопоставляется один к одному и даёт «совпали по имени и
  размеру», но никогда «одинаковы». `where`, `missing`, `only`, `mklist` — строки-счётчики.
- Подсказка **«возможно, переименована»** (`query.renamed`): копии нет ни по хешу, ни по имени и размеру, но есть файл
  того же размера и той же даты изменения (секунды) с другим именем; только от 1 МБ; при разных S/C-хешах — нет.
  Копией не считается, итоги и вердикты не меняет; последнее слово — за хешем (пересканирование).

**Скорость.** Поиск совпадений — по ключам, а не по парам файлов: временная таблица ключей снаружи (`CROSS JOIN`),
`files` — через `INDEXED BY files_name` (имя, размер, диск) или новый частичный индекс `files_sizetime (size, mtime)
where size >= 1 МБ`. Без явного порядка SQLite (без ANALYZE) выбирал внешним циклом все файлы диска — 10+ минут на HDD09.
Так же переписаны `unhashed` (only, candel) и `where` для файлов без хеша: `only HDD09` было 423 с.

**.m2t и .dv — видео.** Сканер 1.5.0 хеширует их (полная опись и пересканирование; правила выборки v3, задания v1/v2
дочитывают их при продолжении). В базе это класс «фото и видео без хеша», в таблице `folders` — столбец «видео». В
старых описях они без хеша: пересканировать их папки («Пересканировать папку…»), полная опись не нужна.

**Сканер, пересканирование папок.** Хеш считается у всех обычных файлов (так с 1.4.0); `--hash-all-types` — явная
запись этого в `job.json` (`hash_types: all`, `hash_all_types_flag`) и `result.json` (`hash_types`); режима «только фото
и видео» нет: приём такого скана заменил бы подтверждённые C/S документов папки на N. Пропускаются, как и при описи,
`.env`-файлы и служебные папки ($RECYCLE.BIN, System Volume Information, .git …) и ссылки. Итог для владельца
(`rescan.summary_text`, лог сканера и окно): «Прочитано заново: N (новые M, изменились K, прочие причины). Хеш взят из
прежнего скана (по правилу доверия файлы не менялись с ДД.ММ.ГГГГ): P»; дата — `reused_measured_utc` (bound_ns).

**«Когда измерены хеши»** (`service.hash_dates`, окно «Диски и папки» при выборе одной папки): по `origin` строк папки —
полная опись (дата описи), каждый частичный скан (дата, сколько взято из прежнего скана по `hash_info`, «измерены не
раньше» по `bound_ns`), журналы шаблона (дата из имени), прочее; нет сведений — «дата неизвестна». Считается при ответе,
база не хранит.

**Остановка копирования клавишей Q и повторный запуск.** Строка журнала «уже есть» не понижает запись цели до Z, если по
тому же пути той же цели уже есть подтверждённая запись S/C того же содержимого (тот же SHA-256; если хеш неизвестен —
тот же размер), из этого или прежнего журнала (`apply_log`, тест `RestartTest`). Обход в `mvlist` оставлен — не мешает.

**Область подсказок.** `missing` — 45 и 77; `only` — только другие диски; `candel` — 45 и 77 вне удаляемой папки;
`where` — все диски, в том числе другое место того же диска. В `where` для файлов без хеша «из них с той же датой» теперь
— есть ли на диске тёзка той же даты (раньше — совпала ли дата у первого найденного тёзки), пример пути — первый по
алфавиту.

**BUILD_VERSION 5 → 7** (6 — индекс `files_sizetime`, классы и `folders` для .m2t/.dv; 7 — правило «уже есть» после Q):
при первой команде настоящая база собирается заново целиком — на копии настоящей базы около 5 минут (STATUS.md).

## 12. Перемещение на источнике для любых дисков-целей; раздел «Задания» (15.11.2026)

Код — `catalog/hb_cmd/mvlist.py`, `catalog/hb_core/util.py` (`moved_folder`), `catalog/tasks_page.py`; тесты —
`catalog/test_tasks_move.py`; спор с GPT — `Проверка Архитектуры сортировки файлов\Перемещение_на_любые_диски_v1.md`.

**Имя папки** — набор дисков, где копии подтверждены, на момент переноса: `ПЕРЕНЕСЕНО → 78`, `… → 45 и 78`,
`… → 45, 77 и 78` (номер — имя без «HDD», по возрастанию; Flash05 — как есть). Прежние имена не меняются: {45, 77} —
`45 и 77`, {45} — `только 45`, {77} — `только 77`. Метка тома в имя не входит (она меняется). Перенесённый файл больше
не переносится, даже если позже его скопируют ещё куда-то. База понимает любое имя по префиксу «ПЕРЕНЕСЕНО → »:
исходный путь — без первой части, решения владельца действуют по нему.

**Когда файл переносится** (всё сразу):
1. Обязательные цели — все диски, куда файл ставило любое задание копирования с этого физического носителя
   (`список.tsv`, носитель — по серийному номеру в `тома.tsv`; путь — подпапка источника + путь строки), и все диски
   из строк журналов, включая ошибки. Задание не сделано — файл «ждёт задания «…»»; ошибка — «копирование не удалось».
   Старые скрипты 11–12.11 (`OLD_LOGS`, `FOLDER_MOVES`) обязательными целями не считаются.
2. На каждой цели в месте назначения из журнала — запись S или C с SHA-256 этой версии. Версия: у файла с хешем — хеш
   описи; у файла без хеша — SHA-256 прочитанного при последнем копировании (и в описи известна дата изменения).
   Связь с текущим файлом — модель доверия метаданным: шаблон перед переносом сверяет размер и дату с описью; это не
   доказательство неизменности (дату можно подделать), как и для файлов с хешем.
3. Есть 45 или 77 среди целей — файл подтверждён и на 45, и на 77 (прежнее правило).
4. Не в «ПЕРЕНЕСЕНО → …», не под решением владельца; путь после переноса не длиннее 259 символов (политика
   совместимости с Проводником; длиннее — остаётся на месте, в предпросмотре отдельной строкой).
5. `--task`: только файлы списка этого задания и только когда обработаны все его строки. Источник HDD45/HDD77 —
   задание создаётся только с `--allow-main` (в окне — отдельный вопрос).

**Известная ошибка сборки (не исправлена здесь):** строка «уже есть» при повторном запуске задания после Q пишет запись

пришла из журнала того же задания и раньше в нём была строка «скопирован…» для той же цели и того же пути с тем же
хешем; предпросмотр говорит, сколько таких.

«готово» или «готово с ошибками», окно один раз за сеанс предлагает «Разложить на источнике…».

## 14. Пересканирование: выбор типов файлов для хеша (16.11.2026, сканер 1.6.0)

Код — `catalog/hash_types.py` (правило окна), `scanner/rescan.py` (`hash_rule`, `wants_hash`, `by_types`),
`scanner/portable.py` (`run_partial`, `hash_types_of`), окно `catalog/rescan_dialog.py`, `service.rescan_argv` /
`rescan_start` (параметр `cats`) и `service.rescan_confirmed`. Тесты — `scanner/test_hash_types.py`,
`catalog/test_rescan_folders.py` (`TypesRuleTest`, `test_selected_types_scan_is_accepted`, окно).

**Окно.** Под «Перечитать всё» — «Считать хеш у файлов:» с галочками «Все типы» и семью типами «Что копировать»
(подписи — `directions_page.CAT_LABELS`). По умолчанию все. «Все типы» ставит и снимает все; отмечены все семь — она
отмечена сама. Ни одного — «Начать сканирование…» неактивна. Под галочками одна строка по предпросмотру (файлы не
читаются): «Будет прочитано примерно N файлов, X ГБ», и если есть — «Без хеша останется M файлов невыбранных типов»
и красным «у K из них в базе сейчас подтверждённый хеш — после приёма скана подтверждение пропадёт» (K — пути в
базе с ev S или C ∩ файлы невыбранных типов без годного прежнего хеша сканера). После запуска галочки не меняются:
продолжение задания идёт по правилу, записанному в задании (окно передаёт только `resume <задание>`). Если базу
прочитать не удалось (число K неизвестно) и типы выбраны не все, вопрос перед запуском прямо говорит «не удалось
проверить, сколько подтверждённых хешей пропадёт… Продолжить?»; известное K тоже повторяется в вопросе.
Продолжение задания «перечитать всё» не перечитывает файлы, уже прочитанные в этом же задании (проверяются тем же
правилом доверия), и не включает их в оценку «осталось прочитать».

**Одно правило типов.** Тип файла — только `derived.copy_kind`. Сканер ядро не импортирует, поэтому окно передаёт ему
готовое правило ключами: `--hash-ext` (расширения выбранных типов — когда «Другие» не выбраны) или `--hash-skip-ext`
(расширения невыбранных — когда «Другие» выбраны: это остаток, перечислить его нельзя), плюс `--hash-skip-names`
(`JUNK_NAMES` и `~$*`) и `--hash-skip-path-re` (`build_pilot.CACHE_RE`): служебные по имени и по пути — мусор при
любом расширении. Тип расширения окно узнаёт вызовом самого `copy_kind` на имени `f<расширение>` (непустой файл).
Тест сверяет `rescan.wants_hash` с `copy_kind` для всех 126 неполных выборов × все известные расширения (и в верхнем
регистре), неизвестное, без расширения, `a.jpg.exe`, служебные имена, пути кэша, размеры 1 байт / 5 МБ / 0; и что
ключи окна, разобранные самим сканером (`portable.hash_types_of`), дают то же правило, что оценка окна.
Единственное расхождение — пустая программа (`x.exe`, 0 байт) при выбранных «Других»: сканер её «хеширует» (0 байт),
`copy_kind` — «программа»; базе хеш пустого файла не нужен (`scan_row`), на результат не влияет.

**Сканер 1.6.0.** Файл выбранного типа — как раньше (прежний годный хеш берётся, иначе читается). Невыбранного:
годный прежний хеш берётся (то же правило доверия, раздел 10, содержимое не читается), иначе файл не читается и
строки в `hashes.sqlite` не получает (это не «не прочитано»: в `result.json` — `skipped_files/bytes`, в журнале —
«без хеша (тип не выбран)»). «Перечитать всё» с выбором — перечитываются только выбранные типы; невыбранные берут
годный прежний хеш (S не теряется). Правило — в `job.json` и `result.json`: `hash_types` = `'all'` или
`{mode, ext, junk_names, junk_path_re}`, `hash_scope` = `all_regular_files` / `selected_types`.

**«Все типы» = прежнее поведение.** Ключей выбора нет, окно передаёт `--hash-all-types` (как раньше): хеш у всех
обычных файлов, в том числе у программ, системных и временных. При неполном выборе программы, системные и
временные файлы хеш не получают — их нельзя выбрать (они не копируются никогда). Без ключей и со старым ключом сканер
работает как 1.5.0. Ключи выбора взаимоисключающие (и с `--hash-all-types`), только с `--folder`; `--hash-ext` с
пустым списком — отказ.

**База.** Сборка не менялась (BUILD_VERSION прежний): формат описи и хешей тот же; файл без строки хеша — N, как
раньше файл без хеша. Значит, подтверждение S/C у файла невыбранного типа, который сканер не смог подтвердить
прежним хешем (изменился, новый, C — из журнала копирования, сканеру не виден; на FAT/exFAT — все), после приёма
пропадает (N). Ошибка консервативная («недостаточно подтверждений», а не ложное «можно удалять»); окно предупреждает
числом K до запуска.

**Критики (по одному раунду).**

| Критик | Замечание | Решение |
|---|---|---|
| GPT | Пустой файл: `copy_kind` — «Другие», таблица по расширению — свой тип | Частично: пустой файл — «Другие» и в сканере (`wants_hash(size=0)`); пустая программа — описанное безвредное расхождение |
| GPT, DeepSeek | Служебные по имени и пути (`~$x.docx`, кэш монтажа) — по одному расширению правило не то же | Принято: ключи `--hash-skip-names`, `--hash-skip-path-re` из тех же `JUNK_NAMES` и `CACHE_RE`; тест на них |
| GPT, DeepSeek | Оценка при «Перечитать всё» и для невыбранных | Учтено: предпросмотр хранит по каждому файлу «годен ли прежний хеш» без учёта «перечитать»; тест оценки = скан |
| GPT | K — по степени S/C, а не по `sha not null` | Принято: `ev in (S, C)` |
| GPT | Тест «только фото» с .mp4; проверки эквивалентности мало | Принято: полный перебор выборов, имён, путей и размеров; «Все типы» — отдельно, против прежнего поведения |
| DeepSeek | «Все типы» ≠ сумма 7 галочек (программы, мусор) | Оставлено намеренно (прежнее поведение); сказано в подсказке галочки и здесь |
| DeepSeek | `--hash-all-types` + `--rehash-all` не должны стать ошибкой | Так и есть: конфликт только между ключами выбора; тест |
| DeepSeek | Пустой выбор | Принято: окно не даёт начать; сканер отклоняет пустой `--hash-ext` |
| DeepSeek | Продолжение задания с другим выбором | Правило — из `job.json`; в окне галочки после запуска неактивны |
| DeepSeek | «Перечитать всё» сотрёт S у невыбранных | Не так: у невыбранных прежний хеш берётся и при «перечитать всё»; тест |

## 15. Окно «Список файлов», автосохранение отметок, пробелы в путях (16.11.2026, этап 16 логики v3)

Документ и итог критиков — `Проверка Архитектуры сортировки файлов\Логика_v3_разбор_носителя.md`, раздел «Этап 16».
Код — `catalog/filelist_window.py`, `service.file_list` / `nohash_info` / `disk_hash_info` / `contested_count`,
`hb_core/razbor.py` (`planner(…, collect=…)`, `contested_rows`), `razbor_page.py`, `disks_page.py`; тесты —
`test_logic_v3` (`SpacesTest`, `FileListTest`), `test_razbor_page` (`SaveTest`, `FileModelTest`, `FileWindowTest`),
`test_disks_page`, `test_copy_template_review` (`Template26`), `scanner/test_rescan`.

- **Отметки сохраняются сразу.** Кнопок «Сохранить отметки» и «Отменить все несохранённые» нет. Правка (галочка,
  перетаскивание, режим) пишется тем же `service.add_marks_batch` (те же проверки, одна строка-пакет под замком, копия
  таблицы в архив) на следующем шаге цикла событий, без окна предпросмотра. Пакет в пути считается сохранённым
  (`Model.inflight`): правка во время записи сравнивается с ним и пишется следующим пакетом. Отказ или ошибка —
  сообщение, черновик этого пакета забывается (на экране — сохранённое). «Отменить последнее» — новой строкой с прежней
  своей отметкой папки («как у родителя» снимает свою отметку и строки не прибавляет, если своей не было). Перед сменой
  носителя, закрытием окна и «Подготовить задания» черновик записывается; не записался — вопрос. Отметку, изменённую
  другой программой между щелчком и записью, перезаписывает последняя правка (как и прежде при «Сохранить»).
- **Списки «Разбора»** (к копированию на диск, уже есть, не подходит по типу) — `planner(collect=(направление,
  исходы))`: исход каждого файла — тем же расчётом, что числа ячейки; файлы без хеша, которые расчёт берёт суммами
  папок, читаются поштучно только в нужных папках, их число сверяется с суммами (расхождение — «ИТОГ НЕВЕРЕН» в окне).
  В списке «к копированию» — все файлы с исходом «копировать» без копии на этом диске; «войдёт в задание» (представитель
  содержимого и файлы без хеша) = часть Б = число в ячейке; повторы того же содержимого и заблокированные — со своим
  «Почему». «Где копия» — все записи с тем же SHA-256 на дисках направления и на 45 и 77 (S/C; Z/U/X — с пометкой «не
  проверена»). Файл в списке один раз (исход файла единственный).
- **«Без хеша»** — одно условие: `sha` пуст и `size > 0` (Z/U/X тоже: у них хеш не измерен). Столбец «Без хеша» дерева
  «Дисков и папок» и строка над деревом — один проход по записям носителя без хеша (`nohash_info`, без агрегата в базе:
  `BUILD_VERSION` не менялся); кэш окна — до новой сборки базы. «частичных: N» → «после полной описи N раз
  пересканированы выбранные папки (M папок)» — N = разные времена частичных сканов в `scan_folders`, а не число папок.
- **Спорные** — `contested_rows` (поштучно; `contested` — свёртка по папкам): файл (диск, путь) один раз, причины через
  «; ». Число на кнопке «Пересчитать хеши спорных файлов (N)» — в фоне, для выделенной папки или всего носителя.
- **Уникальные** — файлы с хешем, подтверждённая копия (S/C) которых есть только на этом носителе (`presence.ndisks =
  1`); без хеша — числом «неизвестно».
- **Окно** открывает «Открыть в Проводнике» только по букве подключённого носителя (`service.disk_letter`, серийный
  номер тома); сохраняет в Excel видимые строки (больше 1 048 575 — вопрос и CSV «;» UTF-8 с BOM); «Пересканировать
  папки выделенных» — вопрос с числом папок и файлов, затем прежнее окно пересканирования; после него — «данные
  устарели, «Обновить»». Больше 1,5 млн строк окно не открывает (просит папку поменьше).
- Все новые функции окна читают базу своим соединением только для чтения (`service.ro`) и закрывают его.
