# Сессия 8 ноября 2026: план консолидации и сканер 1.1–1.2

Продолжение [`SESSION_2026-11-07_08.md`](SESSION_2026-11-07_08.md). Документ фиксирует
принятые решения и проверенные факты. Он не разрешает перемещать или удалять файлы.

## 1. Уточнённая задача

- Дисков больше 20, суммарно более 50 ТБ. Одновременно к компьютеру подключается 3–5.
- Нужно: общая карта файлов → группировка «фото / видео / год съёмки» → ручной
  отбор временного и рабочего → сборка важного на одном диске 18 ТБ. Не влезающее
  (например, RAW) — на отдельные диски 3–4 ТБ.
- Одну копию каждого файла не трогать и помнить, где она лежит (на случай сбоя
  финального диска). Третьи и дальнейшие копии удалять.
- **Диск 18 ТБ уже содержит около 70 % нужного** и только копии с других дисков;
  внутри него тоже есть дубли. Подключается по SATA.
- Диски 3–4 ТБ заняты данными. Два из них — WD Red 3 ТБ, хорошие: их освободить
  первыми и использовать для переброски, потом под бэкапы.
- Освобождённые диски — под тематические бэкапы («Фото 2000–2010» и т. п.).
- Есть внешний SSD для быстрого переноса по USB.
- Порядок, заданный пользователем: **сначала сканирование всех дисков, план — потом.**

## 2. Оценка решения на начало сессии

Сильные стороны оставлены: опознание диска по серийным номерам, только чтение,
полный SHA-256 с продолжением, переносной комплект.

Найденные пробелы:
- нет дат съёмки (EXIF/QuickTime) — без них невозможна раскладка по годам;
- порог 1 МиБ отрезал старые фото и короткие видео;
- результаты разрознены по дискам, нет общего каталога и планировщика;
- в окне не было прогресса и прогноза; в журналах — мало сведений о диске.

Факты по HDD01+HDD02 (2,08 ТБ выборки): повторов сверх одного экземпляра — 5,3 %
объёма; около 90 % байтов — видео; RAW (CR2/NEF/ARW) — около 81 ГБ.

**Исправленная ошибка рассуждения.** Вывод «89 % файлов имеют уникальный размер,
хешировать их незачем» был сделан по двум дискам из 20+ и неверен: уникальность
размера можно утверждать только по описи всех дисков. Кроме того, полный хеш нужен
для будущей проверки целостности. Принята гибридная стратегия: готовые хеши
сохраняются; частичные хеши — только для отсева, никогда для решения об удалении.

Критика внешней модели (ChatGPT) принята по существу:
- QuickTime хранит время то в UTC, то в местном — хранить исходное значение,
  источник, предполагаемый год и исправление пользователя;
- формат видео и отсутствие модели камеры — слабая подсказка, не решение;
- событие — один объект (фото, видео, RAW, XMP, документы), физическое разделение
  только для того, что не влезает, с тем же путём;
- жадный выбор резервных дисков — приближение, а не гарантированный минимум;
- форматировать старые диски можно только после полного охвата, включая
  документы и мелкие файлы.

## 3. Согласованный план консолидации (после сканирования всех дисков)

**Эталон.** Диск 18 ТБ сканируется первым и полностью (полный SHA-256, даты
съёмки). Остальные диски сверяются с ним:

| Файл на другом диске | Что значит |
|---|---|
| Размер не встречается на эталоне | Файла там точно нет — кандидат на докопирование |
| Размер совпадает | Нужен хеш, чтобы подтвердить копию |
| Подтверждён хешем | Уже есть на эталоне — резерв или лишняя копия |

**Порядок на эталоне.** Дубли внутри 18 ТБ — не резерв, их можно убрать, оставив
один экземпляр. Раскладка по годам/событиям внутри одного тома — переименования без
перезаписи данных, с журналом «было → стало». Параллельно — ручной отбор.

**Целевая схема — каскад:**
- копия 1 — финальный диск 18 ТБ, упорядоченный;
- копия 2 — тематические бэкапы на освобождённых дисках, зеркала разделов финального
  диска с той же структурой;
- готов тематический бэкап → экземпляры раздела на старых дисках становятся третьими
  копиями → после свежей проверки их можно удалить → освобождается следующий диск.

**Правило освобождения диска.** Диск можно очистить, только если **каждый** файл на
нём (включая документы и мелкие) после свежей проверки хешем есть ещё минимум в двух
местах на двух разных физических дисках, одно из них — финальный. Не прошедшие
правило файлы образуют «набор эвакуации». Планировщик считает для каждого диска
стоимость освобождения: сколько байт эвакуировать и куда.

**Первые кандидаты** — два WD Red 3 ТБ (приоритет пользователя учитывается как вес;
если их освобождение дорого, планировщик может предложить сначала «дешёвый» диск).
Источники места для эвакуации: свободное место на 18 ТБ; третьи копии на старых
дисках; внешний SSD как временная вторая копия.

**Роль внешнего SSD:** временная вторая копия, перенос между компьютерами, буфер при
нехватке разъёмов. Ускорения копирования HDD→HDD он не даёт. Файл, лежащий только на
SSD, не считается сохранённым.

**Копирование:** только копирование, хеш считается при чтении источника, затем
назначение перечитывается и сверяется. Удаление — отдельная операция.

**Будущие компоненты:** общий каталог; интерфейс отбора; планировщик (источники,
назначения, защищённые копии, свободное место, порядок подключений); исполнитель
(копирование, проверка, журнал, продолжение). Похожие, но не идентичные фото — позже,
на готовом финальном диске (digiKam, Czkawka).

## 4. Сканер 1.1.0

- Панель «Ход работы»: этап, процент, объём и файлы, скорость, остаток времени
  («1 ч 30 мин») и время завершения. Скорость — за последние 10 минут чтения; файлы с
  готовым хешем не входят в прогноз. Файлы идут от мелких к крупным, поэтому прогноз
  в начале завышен (на HDD03: 3 ч 07 мин в начале, фактически 15 мин).
- Рабочий процесс публикует машиночитаемый прогресс (`--progress-file`).
- Полная идентичность носителя: модель, производитель, прошивка, серийный номер,
  ёмкость, шина, HDD/SSD, состояние, разметка, GUID раздела и диска (GPT) или подпись
  MBR, смещение раздела, метка, серийный номер тома, путь тома, буква, компьютер.
  GUID и подпись MBR записаны на самом диске и переживают смену буквы и компьютера.
  Хранится в `job.json` (`identity_at_registration`), `runs.jsonl` (каждый запуск) и
  `log.txt` (читаемый журнал в папке задания).
- Колонка «Уже сканирован» и защита от выдачи занятого номера другому диску.
- Формат задания и правила выборки не менялись: задания 1.0.1 продолжаются.

## 5. Единая структура результатов

```
C:\course_claude\СКАНИРОВАНИЕ ДИСКОВ\
  Реестр дисков.md / .csv     ← пересоздаются после каждого сканирования и импорта
  ПРОЧТИ.md
  HDDxx - модель - ёмкость - метка\
    HDDxx_<код задания>\      ← job.json, inventory.sqlite, inventory_summary.json,
                                 hashes.sqlite, result.json, runs.jsonl, log.txt
  _Журналы окна\              ← журналы окна сканера
  _Архив\                     ← исходники первичного сканирования, заменённые задания
```

- Сканирование и импорт сами создают папку диска; уже существующая папка диска
  используется повторно, даже если метка изменилась.
- Реестр предупреждает: один номер у разных дисков, один диск под разными номерами,
  задания по старым правилам.
- HDD01 и HDD02 переведены из первоначального формата в формат задания: опись
  скопирована побайтно, хеши выделены из общей базы и сверены построчно, затем
  проверены продолжением 1.1.0 (все хеши подтверждены, файлы не изменились).
  Предварительно установлено, что прежняя выборка в точности совпадает с правилами
  переносного сканера.

## 6. Сканер 1.2.0

**Правила выборки v2** (решение пользователя по данным трёх дисков):

| Тип | Порог SHA-256 |
|---|---|
| Фото JPEG/HEIC | от 50 000 байт |
| Прочие изображения и RAW | от 150 000 байт |
| Видео | любой ненулевой размер |

Основание: в диапазоне 50–150 КБ лежат и мусор («3D Tour» — 665 плиток, WordPress),
и семейные фото («С дачного компа» — 952, «Цветы - мамины вышивки» — 736, «МамаМ» —
264). Ниже 50 КБ — в основном миниатюры (на HDD02 — 71 тыс. JPEG). Видео меньше
1 МиБ — единицы, но это могут быть ролики 3GP со старых телефонов.

**Добор.** Задание по правилам v1 при продолжении переводится на v2: опись уже
содержит мелкие файлы, читаются только новые выбранные, готовые хеши сохраняются.
Перевод фиксируется в `job.json` (`policy_history`), `runs.jsonl`, `log.txt`; старые
версии программы после этого отказываются продолжать задание. Правила v1 сохранены
байт в байт, чтобы старые задания распознавались. Добор HDD01: +8 263 файла, 2,6 ГБ,
4 мин; HDD02: +2 048 файлов, 0,7 ГБ, 1 мин.

**Журналы окна** — в `<папка результатов>\_Журналы окна`. Аварийная остановка
пишется и в `log.txt` задания.

**Массовый перенос:** экспорт всех завершённых заданий (неизменённые пропускаются,
обновлённые кладутся рядом новой копией); импорт целой папки с флешки; более новая
версия задания (больше хешей) заменяет прежнюю, прежняя уходит в
`_Архив\Заменённые задания`; более старая отклоняется.

  занятые номера. Номера выдавать заранее, диапазонами на компьютер, и подписывать
  диски.
