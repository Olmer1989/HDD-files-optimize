# Структура программы: небольшие файлы, правка блока без чтения тысяч строк

17.11.2026. Проект Claude по требованию владельца, проверен критиками DeepSeek (`deepseek-v4-pro`) и GPT-Sol
(`gpt-6.1-sol`): 14 + 11 замечаний, все учтены ниже (таблица — в разделе 4). **Пилот «Разбор носителя», шаг А — сделан (раздел 5); «Список файлов», шаг А — сделан (раздел 6).**

## Требование владельца
- Дизайн и отдельные блоки экранов правятся без чтения тысяч строк.
- В файле `.py` — **не больше 600 строк** (цель — до 400). Проверяет `catalog/test_modules.py`.
- Критики проверяют все решения, в том числе каждый шаг переноса.

## 1. Как будет устроено

```
catalog/
  app.py, ui_common.py, disk_ui.py      главное окно и общее (как сейчас)
  ui/style.py                           ВСЕ цвета, шрифты, стили (QSS, HTML, QColor берут отсюда)
  ui/<экран>/                           razbor, filelist, tasks, commands, explorer, directions, disks, overview
      page.py          сборка экрана: создаёт блоки, связывает сигналы (до 300 строк)
      view_<блок>.py   один видимый блок: плашка, дерево, ячейка «Копировать», кнопки, диалог
      texts_<блок>.py  видимые владельцу слова и HTML этого блока, без Qt
      model_*.py       данные экрана без Qt (отметки, галочки, «уже есть»)
      flow_*.py        фоновые процессы с записью (автосохранение, задания, спорные)
  service/                              бывший service.py, по темам: write (замок и запись таблиц владельца),
                                        read, rescan, tasks, directions, family, filelist, razbor, copy_retry
  hb_core/, hb_cmd/                     ядро и команды (как сейчас; большие файлы тоже делятся)
  tests/<экран>/test_<блок>.py          тесты зеркально, каждый файл до 600 строк
```

**Договор для правок:**

| Что меняем | Какой файл |
|---|---|
| формулировку, подпись, плашку | `texts_<блок>.py` этого блока |
| цвет, шрифт, отступ | `ui/style.py` |
| расположение или поведение блока | `view_<блок>.py` |
| подсчёт, отметки | `model_*.py` |
| запись, фоновая работа | `flow_*.py` |

Нейросеть читает нужный файл и, при необходимости, `page.py` (связи) и тест блока. Быстрые тесты блока — без окна,
секунды; полный прогон с окном (3 минуты) — только перед коммитом.

**Правила слоёв (проверяет `test_modules`):** `style`, `texts_*` → `model_*` → `view_*`, `flow_*` → `page`. Блоки
(`view_*`) не импортируют друг друга — общаются через сигналы, связывает `page.py`. Новые файлы не импортируют старые
«переходники». Фоновые задачи принадлежат `flow_*`; приём результата — в главном потоке через существующую защиту
`ui_common` (окно закрыто — результат отбрасывается).

## 2. Как переносим (без риска для данных)

**Шаг А — чистый перенос, поведение не меняется.** Большой класс делится на части-«примеси» (`class RazborPage(TreeMixin,
CellMixin, AutosaveMixin, …)`): методы переезжают в свои файлы без единой правки, у класса тот же интерфейс. Так же
`Model`. Тесты зелёные до и после; тексты ячеек и плашек сравниваются снимком (до = после).

**Шаг Б — вынос текстов и стилей.** Слова и цвета из `view_*` уходят в `texts_<блок>.py` и `ui/style.py`; блоки получают
готовые данные. Отдельный коммит, своя проверка.

**Подготовка к каждому шагу (замечания критиков):**
- **Подмены в тестах.** До переноса составить список всех `mock.patch`. Тесты, подменяющие имя в модуле (`rp.QMessageBox`,
  `sv.X`), переводятся на подмену там, где имя используется, или на подмену метода класса (`QMessageBox.question`). Без
  этого после переноса могли бы всплыть настоящие диалоги.
- **`service.py` → пакет `service/`** заменяется за один коммит: старый файл удаляется, проверяются `service.__file__` и
  `sys.modules` (нет двух копий). `service/__init__.py` отдаёт прежние имена. Замок записи таблиц, границы записи и
  соединения с базой остаются как есть и живут только в `service/write.py`; список всех мест записи — до переноса.
- **«Переходники»** (`razbor_page.py` и др.) — временные, до 60 строк; удаляются, когда тесты переведены.

## 3. Порядок и критерий готовности

1. **Пилот: «Разбор носителя»** (`razbor_page.py`, 3 137 строк). После шагов А и Б — проверка выгоды: свежему агенту
   дать 3 типичные правки владельца (надпись, цвет, блок) и замерить, сколько файлов и строк он прочитал и сколько
   минут ушло. Продолжаем, только если правка заметно дешевле.
2. `filelist_window.py` → `ui/filelist/` (шаг А сделан, раздел 6).
3. `service.py` → `service/` (до остальных экранов: им всем нужен).
4. `tasks_page`, `commands_page`, `explorer_page` + `explorer_diff`, `directions_page`, `disks_page`.
5. Ядро и команды: `hb_core/razbor.py`, `hb_cmd/mvlist.py`, `build_pilot.py`.
6. Тесты больше 600 строк — по своим экранам, вместе с переносом экрана.

Каждый пункт — один свежий субагент, план пункта — обеим моделям критика до кода, готовый код — им же; основной чат —
тесты и коммит. **Готово, когда список долга `FILE_DEBT` пуст** — ни одного файла больше 600 строк.

Проверки на каждом шаге: все тесты зелёные; снимок текстов до = после; ключевые действия экрана (галочка, автосохранение,
«Показать список», смена носителя) в тестах; программа запускается из `catalog\app.py`; `test_file_size`.

## 4. Замечания критиков и решения

| Замечание | Решение |
|---|---|
| Подмены `mock.patch` перестанут действовать после переноса (оба, высокая) | принято: список подмен до переноса, перевод тестов |
| Как сохранить интерфейс `Model` и `RazborPage` при делении (GPT 2) | принято: «примеси» — тот же класс и интерфейс |
| Перенос «без правок» противоречит выносу текстов (оба) | принято: шаг А (чистый перенос) и шаг Б (тексты) раздельно |
| `service` пакетом: подмены, циклы, две копии модуля (GPT 3–4, DeepSeek 1, 6) | принято: атомарная замена, проверка `sys.modules`, импорт подмодулей по отдельности |
| Замок и запись SQLite (GPT 5) | принято: только в `service/write.py`, границы записи не меняются |
| Не у всех больших файлов есть этап; «долг» бессрочный (GPT 6, DeepSeek 7) | принято: у каждого файла этап, критерий — пустой `FILE_DEBT` |
| Общие файлы окна и порядок импорта (GPT 7, DeepSeek 2, 5) | принято: правила слоёв в `test_modules`, без импорта переходников |
| `texts.py` / `style.py` сами станут большими (GPT 8, DeepSeek 8) | принято: тексты — по блоку (`texts_<блок>.py`), стиль — по разделам при росте |
| Цвет задаётся разными способами (GPT 9) | принято: QSS, HTML, `QColor` и делегаты берут константы из `ui/style.py` |
| Жизненный цикл фоновых задач (GPT 10) | принято: задачи — в `flow_*`, приём — через защиту `ui_common` |
| Снимок текстов не ловит поломки расположения (GPT 12) | принято: тесты ключевых действий + запуск окна; осмотр владельцем после пилота |
| Сборка программы (GPT 13) | учтено: exe окна ещё не собирается; при сборке — проверить новые каталоги |
| Выгода не доказана (GPT 14) | принято: замер на пилоте, без выгоды — не продолжаем |
| `service` переносить раньше экранов (DeepSeek 9) | частично: пилот на «Разборе» не трогает `service`, затем сразу `service` |
