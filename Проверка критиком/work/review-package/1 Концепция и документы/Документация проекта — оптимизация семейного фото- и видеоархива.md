# Документация проекта: оптимизация семейного фото- и видеоархива

Состояние на **12 ноября 2026**. Документ описывает проект целиком: зачем он, как устроен,
что сделано, что получается, где были ошибки и что дальше. Подробные правила и цифры —
в рабочих документах (раздел 10), этот документ — общая картина.

---

## 1. Задача

Семейный фото- и видеоархив за 25+ лет разбросан примерно по 56 носителям: внешние HDD,
SSD, флешки, карты памяти. Одни и те же снимки лежат во многих копиях под разными
именами и в разных папках; часть носителей старая или повреждена; где «главная» копия —
неизвестно.

**Цель:**

1. Собрать **одну упорядоченную копию всего семейного архива** на большом диске —
   **Диск 45-16тб** (HDD45, Seagate 16 ТБ, в Windows 14,55 ТБ; буква обычно G:).
2. Держать **вторую полную копию** на **Диске 77-14тб** (HDD77, Seagate 14 ТБ, в Windows
   12,7 ТБ; буква обычно S:).
3. То, что к семейному архиву не относится (фильмы, рабочие проекты, оцифровки, папки
   родственников), вынести на **отдельные диски**, тоже по возможности в двух копиях.
4. Освободить остальные носители, не потеряв ни одного уникального файла.

**Главный принцип:** ничего не теряем. Удаляет файлы только пользователь, сам, и только
после того, как проверено, что каждый удаляемый файл уже есть **и на 45, и на 77**.

## 2. Замысел: как это решается

Работа идёт по описям, а не «на глаз»:

1. **Опись каждого носителя.** Переносной сканер проходит диск и записывает все файлы
   (путь, размер, даты), а для фото и видео считает **SHA-256** — отпечаток содержимого.
2. **Общий каталог.** Описи всех носителей сводятся вместе. Одинаковый SHA-256 означает
   один и тот же файл, как бы он ни назывался и где бы ни лежал. Так видно, сколько у
   каждого файла копий и где они.
3. **Решения пользователя.** Что семейное, что рабочее, что не нужно — решает
   пользователь; решения записываются.
4. **План размещения.** Что на какой диск.
5. **Исполнение.** Копирование скриптами по спискам из каталога, проверка, журнал.
   Удаление — только пользователем и только после проверки.
6. **Вторые копии и освобождение дисков.**

Решения принимаются **по уже посчитанным SHA-256 из базы** — файлы повторно не
перечитываются (это часы работы), кроме спорных случаев.

## 3. Как устроено

### 3.1. Сканер

- Переносной комплект для Windows 10/11 со встроенным Python, запускается без установки,
  только читает носитель. Версия 1.3.2.
- На каждый носитель — задание: `job.json` (паспорт: модель, серийные номера, серийный
  номер тома), `inventory.sqlite` (все файлы), `hashes.sqlite` (SHA-256 фото и видео),
  журналы. Прерванное сканирование продолжается с места остановки.
- SHA-256 считается для JPEG/HEIC от 50 КБ, RAW и прочих изображений от 150 КБ, видео
  любого размера. Мелкие картинки (превью, иконки) не хешируются.
- Каждому носителю пользователь даёт постоянный номер: HDD01…, Flash01…
- Сканирование закончено 10.11.2026: 56 заданий (34 диска и SSD, 22 флешки и карты),
  около 2,46 млн фото и видео с хешами. Повторных сканов не будет.

### 3.2. Сводная папка и каталог

- Все задания лежат в `РЕЗУЛЬТАТЫ СКАНИРОВАНИЯ - сводные` (в Git не попадает: там
  серийные номера и личные пути). Там же автоматический «Реестр дисков».
- Скрипты на Python в папке `catalog/`:
  - `build_pilot.py` — общие функции (найти задания, загрузить диск) и черновой каталог в Excel;
  - **`disk_vs_45_77.py`** — главный инструмент сверки: что лежит на диске N и что из
    этого уже есть на 45 и 77, по папкам, за 2–5 секунд; `--list` выгружает Excel со
    всеми файлами, которых нет ни на 45, ни на 77, и показывает, на каких дисках они ещё
    есть;
  - генераторы списков копирования (`make_copy_to_g.py`, `make_move_to77.py`,
    `make_copy_j_missing.py` с наборами) — готовят список файлов и данные для скрипта.
- Результаты расчётов, списки и скрипты для пользователя — в `Каталог дисков\` (вне Git).

### 3.3. Как распознаётся «тот же файл»

| Случай | Как считаем |
|---|---|
| SHA-256 одинаковый | один и тот же файл, сколько бы ни было имён и папок |
| Имя одинаковое, размер разный | разные файлы (камеры начинают нумерацию заново) |
| Имя **и** размер одинаковые, хеш разный | **спорный файл**: одна из копий может быть испорчена; без проверки не удаляется |
| Хеша нет (мелкие файлы, документы) | сравнение только по имени и размеру, приблизительно |

### 3.4. Диски и буквы

Буквы дисков в Windows меняются, поэтому:

- в документах и скриптах диск называется **номером** (HDD45, HDD77, HDD51…);
- в разговоре — **«Диск 45-16тб»** и **«Диск 77-14тб»**; прочие — «HDD51-MyBook-3Тб»,
  «HDD55-MyBook-2Тб», «HDD59-Видео», «HDD31-RAW» и т. п.;
- скрипты сами находят букву по **серийному номеру тома**; перед выдачей путей
  пользователю буква сверяется.

### 3.5. Куда кладутся перенесённые файлы

На Диск 45-16тб и Диск 77-14тб файлы с других носителей кладутся **не сразу в основные
папки**, а в

```
<диск>:\ПЕРЕНОС с других дисков\<номер диска-источника>\<тот же путь, что на источнике>
```

Так всегда видно, откуда пришёл файл. Раскладка по годам и событиям — отдельным этапом
(перегруппировка, раздел 9).

Целевая структура события после перегруппировки:

```
<Год>\<Событие>\JPEG\  RAW\  Видео\  Обработанные\
```

### 3.6. Единый шаблон копирования (с 12.11.2026)

Все копирования «с диска-источника на 45 и/или 77» делаются **одним и тем же скриптом**:
`Каталог дисков\_ШАБЛОН копирования\Копировать.ps1` (версия 2.1) и `Запустить.cmd`.
**Отдельные скрипты копирования под задачу больше не пишутся** (решение пользователя
12.11.2026). Для новой задачи оба файла **копируются без правок** в папку задачи; меняются
только два файла данных рядом со скриптом:

- `тома.tsv` — `<имя диска> TAB <серийный номер тома> [TAB <папка на этом диске>]`;
  **первая строка — источник**, остальные — цели (одна или несколько). Третья колонка
  (с версии 2.1, только для целей) заменяет папку `ПЕРЕНОС с других дисков`. Если
  диска-цели нет под рукой, в его строке указывают серийный номер другого диска и папку
  на нём — так 12.11 файлы для HDD45 направлены на
  `F:\ВРЕМЕННЫЕ ФАЙЛЫ для ПЕРЕМЕЩЕНИЯ на диски\на диск 45`;
- `список.tsv` — `<цель> TAB <путь от корня источника> TAB <размер> TAB <пометка>` и,
  по возможности, пятой колонкой `SHA-256 из описи`.

Запуск — двойным щелчком по `Запустить.cmd`: вопроса «Изменение политики выполнения» при
этом нет, системная политика не меняется. Запуск правой кнопкой («Выполнить с помощью
PowerShell») тоже работает, но Windows иногда задаёт этот вопрос (см. раздел 8).

Что шаблон делает иначе, чем скрипты 11–12.11:

- только копирует; на источник не пишет; не удаляет и не перезаписывает; стирает лишь
  собственный недописанный `.part`;
- считает SHA-256 **из тех же байтов, что читает при копировании** (диск повторно не
  читается), пишет его в журнал и, если в списке есть SHA-256 из описи, сверяет: при
  несовпадении копия не оставляется, в журнале — ОШИБКА;
- если диск не отвечает дольше 120 с, прекращает работу и называет зависший диск;
- файлы любого размера (ошибка с файлами больше 2 ГБ устранена: проценты считаются в
  дробных числах);
- проверяет список до начала (цель есть в `тома.tsv`, путь без `..`, `:` и `/`), при
  нехватке места или совпадении источника и цели не начинает;
- ставит копии дату изменения и дату создания источника.

Проверка шаблона перед выдачей и после любой правки — на тестовых папках:
`powershell -NoProfile -File Копировать.ps1 -TestRoots "ИМЯ1=папка-источник;ИМЯ2=папка-цель"`
(имена — как в `тома.tsv`). Набор теста 12.11: файлы 0 байт, 1 КБ, 9 МБ, **2,3 ГБ**, путь
443 символа, пробел в начале имени папки, кириллица, неверный SHA-256, изменившийся
размер, конфликт, остаток `.part`, повторный запуск, предел ожидания 0 с. Не проверялись:
остановка по Q в настоящем окне и настоящее зависание диска.

Шаблон меняется только в папке `_ШАБЛОН копирования`, с новой версией в первой строке
и повторным тестом; скрипты в папках задач не правятся. Старые скрипты копирования в
папках задач переименованы в `СТАРЫЙ скрипт - НЕ ЗАПУСКАТЬ.ps1.txt`: `Запустить.cmd`
запускает все `.ps1` в своей папке, поэтому второго `.ps1` рядом быть не должно.

Версия 2.1 (12.11.2026): третья колонка в `тома.tsv`; пустой ответ на вопрос «да»
означает отмену. Проверена тем же набором теста.

## 4. Как проходит процесс (рабочий цикл)

1. Пользователь подключает диск и спрашивает: что на нём и чего не хватает на 45 и 77.
2. Claude сверяет диск с описями (`disk_vs_45_77.py`, по SHA-256) и показывает таблицу по
   папкам: что есть на 45, что на 77, чего нет нигде.
3. Пользователь решает: что семейное, что копировать, что не нужно.
4. Claude готовит **список** и **скрипт копирования** (PowerShell) в `Каталог дисков\<задача>\`
   и записывает план в журнал операций.
5. Пользователь запускает скрипт. Скрипт:
   - находит диски по серийным номерам томов;
   - показывает объём и свободное место, спрашивает подтверждение;
   - копирует, показывая процент, скорость и оставшееся время; **Q — остановка**;
   - ничего не удаляет и не перезаписывает; конфликты помечает;
   - после каждого файла сверяет размер и пишет строку в журнал скрипта;
   - при повторном запуске пропускает уже скопированное.
6. Пользователь пишет **«проверь»**; Claude сверяет результат по журналу скрипта и
   отвечает «да» или «нет» со списком того, чего не хватает.
7. Только после «да» пользователь сам удаляет лишнее с исходного диска. Удаление
   записывается в журнал операций.

Всё, что сделано с файлами, заносится в `docs/ЖУРНАЛ_ОПЕРАЦИЙ.md`; изменения
документов и скриптов сохраняются в Git и отправляются на GitHub.

## 5. Правила (кратко)

- **Никогда не удалять без двух копий.** Удаляемый файл должен быть и на 45, и на 77.
- **Удаляет только пользователь.** Скрипты Claude только копируют или перемещают внутри
  диска; вместо корзины для дублей — папка-карантин `_КОРЗИНА_ДУБЛЕЙ`.
- **Сначала копирование, потом «проверь», потом удаление.**
- **Решения — по SHA-256 из базы**, без повторного чтения файлов.
- **Папку пользователя Зои (`Users`) не трогаем** (копировать с неё можно, менять — нет).
- **Скрипты:** прогресс (этап, процент, скорость), остановка по Q, журнал по строке,
  подтверждение перед началом, никаких удалений.
- **Перед выдачей скрипта:** взять за основу предыдущий рабочий скрипт и **запустить новый
  на тестовых файлах** в Windows PowerShell 5.1. Проверка одного синтаксиса не считается.
- **Копирование — только единым шаблоном** (раздел 3.6): скрипт не переписывается под
  задачу, меняются `тома.tsv` и `список.tsv`.
- **Секреты** (ключи API) — только в `C:\secrets\.env`, который заполняет пользователь;
  в коде — только имена переменных.

## 7. Что получается

- **Сверка любого диска — секунды.** Ответ «что здесь есть и чего не хватает на 45 и 77»
  даётся по базе, без чтения дисков.
- **Уникальное видно сразу.** Например, на HDD61 и HDD17 найдены исходники Эквадора,
  которых больше нигде нет, и пары «одинаковое имя и размер, разный хеш» — возможная порча.
- **Место.** Без фильмов, оцифровок, видео севера и рабочих проектов семейный архив
  помещается и на 45, и на 77; запас на 77 небольшой.
- **Ничего не потеряно**: все удаления шли после сверки, кроме осознанных решений
  пользователя удалить ненужное совсем (записаны в журнале).

## 8. Где ошибаемся и чему научились

| Ошибка | Что случилось | Что изменили |
|---|---|---|
| «HDD45 — зеркало G» | на самом деле это один и тот же диск | роли дисков проверяются по серийным номерам |
| Список копирования пропустил конфликт версий (GX010494) | файл с тем же именем уже был на G в другой версии | правила для списков: учитывать «спорные» |
| Скрипт копирования не сработал | в PowerShell `$P` и `$p` — одна переменная | переименование, проверка переменных |
| `\\?\` превратился в `\?\` | экранирование при генерации из Python | обратная косая через `chr(92)` |
| Скрипт без прогресса | пользователь не видел, идёт ли работа | правило: прогресс, скорость, Q |
| Зависание при записи на K: | бокс ACASIS сбоил (сбросы USB), скрипт ждал бесконечно | на K: не писать до проверки SMART и `chkdsk`; карантин вместо корзины |
| Подсчёт «висел» 7 минут | в команде осталась `cat >` без входа и ждала ввода | скрипты пишутся в файл и запускаются отдельно |
| Скрипт «Копировать недостающее» дал 10 137 ошибок | `New-Object FileStream($a + $b, …)`: запятая в PowerShell сильнее `+`, конструктор получил одну строку; скрипт не был запущен перед выдачей | объекты .NET — через `[Тип]::new()`; обязательный тест на файлах; новый скрипт — от последнего рабочего |
| Файлы больше 2 ГБ не копировались (12.11, 4 файла с HDD51) | `[math]::Max(1, $it.Size)` в строке прогресса: Windows PowerShell 5.1 приводит свойство объекта к Int32; тест был только на маленьких файлах | единый шаблон (3.6): проценты в дробных числах; в тесте обязателен файл больше 2 ГБ |
| Вопрос «Изменение политики выполнения» при запуске правой кнопкой (12.11 10:14) | скрипт тот же, что запускался без вопроса в 02:01 (совпадает побайтно); вопрос задаёт команда Windows `Set-ExecutionPolicy`, и только когда PowerShell стартует дольше секунды (так устроена его проверка «интерактивности»); в 10:10–10:30 система ждала сбоящий диск H:. Опытом на этом ПК не подтверждено | запуск через `Запустить.cmd` — вопроса нет |
| Сбой бокса ACASIS, повреждение H: (11–12.11) | сбросы USB с 11.11 15:10; 11.11 21:58 потеряны записи в `K:\$Mft`; 12.11 H: перестал распознаваться; работа с дисками через сбоящий бокс продолжалась, совет `mountvol /p` был лишним и рискованным | при ошибках диска в журнале Windows — остановиться, выключить ПК, диск подключать напрямую по SATA; `chkdsk` на оригинале не запускать |
| Повторное хеширование | долго, пользователь возразил | решения только по SHA-256 из базы |
| Ответы без учёта прошлых копирований | сверка по сканам, сделанным до копирования | генераторы учитывают списки уже скопированного |

Общий вывод: ошибки возникали, когда работа делалась **с нуля вместо повторного
использования проверенного** и когда результат **не проверялся перед выдачей**.

   записать итог.
2. **Закрыть оставшиеся сверки дисков**: для каждого подключаемого диска — таблица
   «чего нет на 45 и 77», скрипт копирования, проверка, удаление пользователем.
   Остались, в частности: HDD55 (остальное: «Фото Франция - рабочие материалы» ~248 ГБ
   на 77, Посольский НГ 2011 ~49 ГБ на 77), HDD53 (V:, решения уже приняты), HDD31-RAW
   (808 ГБ RAW на 77), видео концерта на 77, флешки и малые диски.
3. **Освободить WD Red** (HDD59, HDD31) и заполнить отдельные диски: фильмы, оцифровки
   (2 копии), «Север и Работа», «Саша, Таня, Соммелье» (2 копии). Каждую группу —
   скопировать, проверить, только потом удалять с 45 и 77.
4. **Разобрать спорные файлы** (одинаковое имя и размер, разный хеш): какая копия целая.
5. **Перегруппировка Диска 45-16тб** в `<Год>\<Событие>\JPEG|RAW|Видео|Обработанные`
   по дате съёмки из метаданных, с журналом «было → стало».
6. **Диск 77-14тб — точное зеркало 45** после перегруппировки.
7. **Быстрая проверка результата без полного пересчёта**: обойти диск по именам,
   размерам и датам, сопоставить с описями и журналами копирования, настоящим хешем
   досчитать только спорное и выборку для контроля (идея обсуждена 12.11, отложена).
8. Доработка сканера при необходимости (`.m2t` как видео, таймаут на зависшем файле).

Открытые вопросы — куда относить: папку САЙТ, «ПЕРЕД РЫБАЧЬИМ\Разное», музыку с HDD51;
какой WD Red под что; второй диск для оцифровок; какие диски на 1 ТБ; видео «Тренировки
с Димой».
