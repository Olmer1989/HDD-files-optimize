# Разбор ошибок Claude в проекте «Оптимизация семейного фото- и видеоархива» (11–12.11.2026)

Документ написан Claude (модель Claude Opus 5.5, Claude Code) по требованию пользователя для
независимой проверки другой нейросетью. Цель — честно и проверяемо описать: какие ошибки
допустил Claude, к чему они привели, что из этого уже подтверждено фактами (журналы Windows,
журналы скриптов), что не подтверждено, и в чём пользователь выразил недовольство.

Claude не смягчает формулировки и не перекладывает ответственность. Где причина не установлена
или вина распределена (железо + совет Claude), это сказано прямо.

---

## 1. Контекст

- Пользователь сводит семейный фото- и видеоархив с ~56 носителей на два больших диска:
  **Диск 45-16тб** (HDD45, буква G:) и **Диск 77-14тб** (HDD77, буква S:). Полное описание —
  `Источники информации\Документация проекта — оптимизация семейного фото- и видеоархива.md`.
- Роли: Claude анализирует описи (SQLite с SHA-256 по каждому носителю), готовит списки и
  PowerShell-скрипты копирования; **пользователь сам запускает скрипты и сам удаляет файлы**.
- Ключевые правила пользователя (зафиксированы в `docs/АЛГОРИТМ.md`):
  - ничего не удалять, пока файл не лежит и на 45, и на 77;
  - скрипты: прогресс (этап, процент, скорость), остановка (Q), журнал, никаких удалений;
  - решения — по уже посчитанным SHA-256, без повторного чтения дисков.
- Окружение: Windows 10 Pro 19045, Windows PowerShell 5.1 (скрипты пользователя) и
  PowerShell 7 (инструмент Claude). Внешние диски по USB, в т. ч. двухдисковый бокс
  **ACASIS EC-7352** (UASP) с HDD17 (буква K:, 750 ГБ) и HDD61 (буква H:, 750 ГБ).

## 4. Подробно: скрипт копирования (E2, E3, E4, E7)

**Хронология 12.11:**
- 01:23 — пользователь запускает «Копировать недостающее.ps1» (J: → G:, S:). Результат: 10 137 ошибок
  «Не удается найти перегрузку для FileStream и количества аргументов: 1».
- Причина: `New-Object System.IO.FileStream($LongPrefix + $srcPath, 'Open', 'Read', 'Read', $Buf)`.
  В PowerShell в выражении внутри скобок оператор «запятая» связывает сильнее `+`, и в
  конструктор ушла одна склеенная строка. Предыдущие рабочие скрипты Claude использовали
  `[System.IO.File]::Copy` и этой проблемы не имели.
- Claude исправил на `[System.IO.FileStream]::new(...)` и прогнал тест на временных файлах
  (9 МБ и 1 КБ) в Windows PowerShell 5.1 — тест нашёл ещё 2 проблемы (`[Console]::KeyAvailable`
  без консоли; остаток `.part` мешал повтору), их исправили.
- 01:28 — пользователь запустил исправленную версию (промежуточную). Итог по журналу:
  10 133 файла скопированы с совпадением размера, **4 ошибки** — все файлы больше 2 ГБ (E7).
- **E7 не был найден до 12.11 ~10:20**, потому что тест не содержал файла > 2 ГБ, а журнал
  ночного запуска Claude не проверял (E8).

**Почему так вышло (самооценка):**
- Новый скрипт написан с нуля, а не копией проверенного (после сжатия контекста код
  рабочих скриптов не был у Claude «перед глазами», и Claude их не открыл).
- Ради прогресса внутри большого файла и остановки по Q Claude заменил `File.Copy` на ручное
  копирование кусками — новый код, новые ошибки.
- Проверка синтаксиса была выдана за проверку работоспособности.
- Тест не покрыл граничные случаи (файлы > 2 ГБ — типичны для видео).

**Что требуется исправить (ещё не сделано):** в строке
`Write-Progress -Id 2 … -PercentComplete ([math]::Min(100, 100 * $fileDone / [math]::Max(1, $it.Size)))`
заменить `[math]::Max(1, $it.Size)` на `[math]::Max([int64]1, [int64]$it.Size)`; проверить на
тестовом файле > 2 ГБ. До исправления **скрипт «K - на 45 и 77» запускать нельзя** (в нём есть
файлы > 2 ГБ).

**Оценка причин (Claude):**
- Сбой начался **до** советов Claude: повреждение H: зафиксировано в 08:51, с 09:39 запись на H:
  не проходила по таймауту устройства. Ранее (11.11) по HDD61 было известно: SMART PASSED, но

- **Совет `mountvol /p` был ошибкой Claude.** При зависшем извлечении правильный и безопасный

  могло **усугубить** повреждение корневого каталога H:. Доказать или исключить вклад
  `mountvol` в повреждение по имеющимся журналам нельзя.
- Claude не предупредил о последствиях `/p` и не предложил сначала самый простой вариант.

**Что на кону:** на H: (HDD61) по описи около **136 ГБ фото/видео, которых нет больше нигде**
(главное — исходники «Эквадор 2004», ~91 ГБ). Список: `Каталог дисков\Сверка с 45 и 77\HDD61 -
файлы, которых нет на 45 и 77.xlsx`. На K: (HDD17) — ~300 ГБ, которых нет на 45/77 (из них
~181 ГБ исходников Эквадора нет больше нигде; «Саша, Таня, Наташа» 71,5 ГБ).

**Рекомендации Claude (на проверку):** H: не трогать (`chkdsk /f` не запускать, не форматировать,
ничего не писать); вынуть HDD61 из бокса; снять посекторный образ на другой диск (≥ 700 ГБ);
восстанавливать с образа программами только для чтения (DMDE, R-Studio); K: — сначала скопировать
уникальное, потом проверять файловую систему.

## 7. Вопрос «Изменение политики выполнения» (E12)

- Пользователь: вчера запускал правым кликом, такого вопроса не было.
- Факты (журнал Windows PowerShell, событие 400): **и 11.11, и 12.11** скрипты запускались одной и
  той же стандартной командой Windows «Выполнить с помощью PowerShell»:
  `powershell.exe -Command if((Get-ExecutionPolicy) -ne 'AllSigned') { Set-ExecutionPolicy -Scope Process Bypass }; & '<файл>'`
  (запуски 11.11 13:47, 15:17, 16:43; 12.11 01:23, 01:28, 01:56, 02:01, 10:14).
- Политика выполнения Windows PowerShell 5.1: CurrentUser = RemoteSigned, LocalMachine = Undefined;
  в журнале нет записей о её изменении. Claude её не менял. На скриптах нет отметки
  «загружено из интернета» (Zone.Identifier).
- Вопрос задаёт сама команда Windows (`Set-ExecutionPolicy -Scope Process`), он относится только к
  одному окну. Почему 11.11 пользователь его не видел — **не установлено**. Возможно, вопрос
  был и в тот раз, а ответ по умолчанию («N», Enter) не мешает запуску локального скрипта при
  политике RemoteSigned. Это гипотеза, не факт.
- Ошибка Claude здесь — первый ответ был дан без проверки фактов.

## 8. Общие причины ошибок (самооценка Claude)

1. **Работа с нуля вместо повторного использования проверенного** (скрипты, приёмы).
2. **Выдача без проверки**: синтаксис вместо реального запуска; тест без граничных случаев.
3. **Утверждения о состоянии без проверки фактов** (не открыты журналы скриптов, не проверен
   источник вопроса о политике).
4. **Системные команды без оценки последствий** (`mountvol /p`) и без предупреждения; не
   предложен самый простой и безопасный путь первым.
5. **Невнимательность к деталям PowerShell** (приоритет операторов, разбор `{…}`, перегрузки
   .NET-методов при `Int32`/`Int64`, регистронезависимые переменные).
6. Длинная сессия со сжатием контекста: часть деталей (код рабочих скриптов) не была перед
   глазами, а Claude не восполнил это чтением файлов.

## 9. Что Claude предлагает изменить в процессе (на проверку)

- Новый скрипт — только как копия последнего рабочего с минимальной правкой.
- Перед выдачей — запуск в Windows PowerShell 5.1 на тестовых файлах, включая **файл > 2 ГБ**,
  пробелы и кириллицу в путях, повторный запуск, прерывание.
- Перед любым ответом о состоянии — проверка журналов скриптов и журнала Windows.
- Никаких системных команд (mountvol, diskpart, chkdsk, политики) без явного описания
  последствий и без предложения сначала самого безопасного варианта.
- Для сложных и рискованных решений — независимая проверка (скилл «Дискуссия» с другой моделью).
