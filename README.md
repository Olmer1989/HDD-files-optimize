# HDD: оптимизация фото- и видеоархива

Инструменты для инвентаризации отключаемых HDD, проверки точных копий по содержимому и подготовки безопасного размещения архива.

## Текущий статус

Реализованы постоянный реестр носителей, инвентаризация метаданных, выборка медиа от 1 МиБ и полные SHA-256 с сохранением результатов после каждого файла. Полные выборки HDD01 и HDD02 завершены без ошибок хеширования: 33 199 файлов, 2 076 028 210 975 байт. Ограничения охвата инвентаризации сохранены в локальных отчётах. Подготовлен переносной сканер для Windows x64 с Python внутри, возобновлением и передачей результатов флешкой.

Автоматическое перемещение и удаление не реализованы. Одинаковые имена/размеры не считаются доказательством дубликата. Равенство содержимого определяется полными хешами; даты файловой системы и имена не входят в SHA-256. Проверка хеша не подтверждает наличие резервной копии или исправность формата медиа.

## Структура

- `docs/SESSION_2026-11-07_08.md` — задача, принятые решения, архитектура, алгоритмы, ошибки и фактические результаты сессии.
- `scanner/README.md` — подробный алгоритм, ограничения и этапы разработки.
- `scanner/PORTABLE.md` — запуск на других компьютерах, экспорт и импорт через флешку.
- `scanner/portable.py` — отдельные локальные задания, идентификация, контрольные точки, защита от сна.
- `scanner/build_portable.py` — сборка автономного ZIP из официального Python с проверкой SHA-256.
- `scanner/inventory.py` — только чтение метаданных.
- `scanner/build_selection.py` — формирование выборки из сохранённых каталогов.
- `scanner/hash_files.py` — полные SHA-256, контроль изменений, контрольные точки.
- `scanner/test_*.py` — тесты на временных данных; исходные архивы не используются.
- `scanner/run_pilot.ps1`, `scanner/run_full.ps1` — локальные PowerShell-запуски. Пути соответствуют текущей рабочей машине и конкретной выборке; перед использованием на другом компьютере адаптировать.
- `Источники информации/` — исследованные источники и материалы подготовки.
- Скрипты в корне — исторические сравнения; сохранены для анализа. Содержат устаревшие пути и сравнения по именам/размерам; не использовать для удаления файлов.

## Локальные данные

Рабочий `scanner/disks.json`, каталоги, хеши, Excel-выгрузки и журналы не публикуются. За основу реестра можно взять `scanner/disks.example.json`; заполнить фактическими аппаратными идентификаторами и размерами. Номер HDD01/HDD02 постоянный, буква Windows временная. При несовпадении/неоднозначности идентификации сканирование прекращается.

Результаты сканирования всех дисков собраны в единой структуре вне проекта: `C:\course_claude\СКАНИРОВАНИЕ ДИСКОВ\` (папка на каждый диск, автоматический «Реестр дисков», описание — `ПРОЧТИ.md` там же; см. `scanner/PORTABLE.md`). Первичные результаты HDD01/HDD02 переведены туда в общий формат; их исходники перенесены без изменений в `СКАНИРОВАНИЕ ДИСКОВ\_Архив\`. Исторический аудит — в `Анализ/` проекта. Эти папки исключены из Git. Одноразовый скрипт миграции первоначальных локальных результатов также не публикуется.

## Проверки

Python 3.11+ (для переносных инструментов); инвентаризация и идентификация предназначены для Windows. Комплект включает Python 3.13.17 x64. Исторические скрипты Excel требуют openpyxl; современный scanner использует стандартную библиотеку Python.

```powershell
cd scanner
py -m unittest discover -p 'test_*.py'
```

Сканирование и хеширование запускаются по инструкции `scanner/README.md`. Не запускать несколько экземпляров хеширования на одну базу; не редактировать архив во время чтения. Удаление потребует отдельного проверенного плана и актуальной проверки независимых копий.

## Правило сопроводительных материалов

Документы и прочие материалы внутри папки поездки/события сохраняются вместе с ней, включая вложенные папки. Несвязанные прочие файлы предполагается выносить в `НЕ ФОТО и НЕ ВИДЕО`, сохраняя исходные пути и номер носителя. Неоднозначные случаи остаются на месте до просмотра плана.
