# HDD: оптимизация фото- и видеоархива

Инструменты для описи 20+ отключаемых дисков (более 50 ТБ), поиска точных копий по
содержимому и подготовки безопасной сборки семейного фото- и видеоархива на одном
диске 18 ТБ с упорядоченными резервными копиями.

## Цель и общий план

1. **Отсканировать все диски** (идёт сейчас). Для каждого диска: опись всех файлов,
   SHA-256 фото и видео, однозначная идентичность носителя.
2. **Составить общий каталог** всех дисков: точные копии, уникальное содержимое,
   события и годы съёмки, стоимость освобождения каждого диска.
3. **Ручной отбор** папками/событиями: что хранить, что временное или рабочее.
4. **Сборка**: диск 18 ТБ — эталон и копия 1 (на нём уже ~70 % нужного);
   освобождённые диски — тематические бэкапы, копия 2. Освобождение дисков — каскадом.

План согласован 08.11.2026 и подробно описан в
[`docs/SESSION_2026-11-08.md`](docs/SESSION_2026-11-08.md). Планирование начинается
только после сканирования всех дисков.

## Текущее состояние

Переносной сканер **версии 1.3.1** работает на нескольких компьютерах; кроме дисков
(HDD…) описывает флешки и карты памяти (Flash…, около 30 штук). Сводка по
носителям и открытые вопросы — в [`STATUS.md`](STATUS.md).

Сравнение копий, планировщик, перенос и удаление файлов **не реализованы**. Программа
только читает архивные диски.

## Файлы проекта

- `scanner/portable.py` — рабочий процесс сканера: идентификация носителя, опись,
  SHA-256 с продолжением, добор, прогресс, экспорт/импорт, реестр дисков.
- `scanner/gui.ps1` — окно сканера (Windows Forms, Windows PowerShell 5.1).
- `scanner/inventory.py` — опись метаданных, только чтение.
- `scanner/build_selection.py` — правила выборки файлов для SHA-256 (версии 1 и 2).
- `scanner/hash_files.py` — чтение файла и SHA-256 с контролем изменений.
- `scanner/build_portable.py` — сборка автономного ZIP с официальным Python 3.13.17.
- `scanner/sorting_rules.json` — правила будущей перегруппировки сопроводительных файлов.
- `scanner/test_*.py` — 35 автотестов на временных данных; архивные диски не используются.
- `scanner/run_pilot.ps1`, `run_full.ps1`, `check_launcher.ps1` — первый локальный путь
  сканирования HDD01/HDD02 (исторический, заменён переносным сканером).
- Скрипты `*.py` в корне — исторические сравнения по именам и размерам. Устаревшие
  пути; не использовать для решений об удалении.
- `publish_github.ps1` — обходной путь коммита из песочницы первой сессии; сейчас Git
  работает напрямую.

## Что не публикуется

Реальный реестр `scanner/disks.json`, серийные номера, базы, каталоги путей, журналы,
Excel-выгрузки и собранный комплект в Git не попадают (см. `.gitignore`). Шаблон
реестра — `scanner/disks.example.json`. Файлы `.env` не читаются и не изменяются.

## Проверки

Python 3.11+ (на основном компьютере), комплект содержит свой Python 3.13.17 x64.
Сторонних пакетов сканер не требует; исторические Excel-скрипты требуют openpyxl.

```powershell
cd scanner
py -m unittest discover -p 'test_*.py'
```

В собранном комплекте: `SELF_TEST.cmd` (автотесты) и `GUI_TEST.cmd` (окно с
настоящим дочерним процессом: успех, ошибка, остановка, прогресс и прогноз).

## Основные правила

- Номер диска (HDD01, HDD02…) постоянный и закреплён за физическим диском; буква
  Windows временная. Диск узнаётся по серийным номерам устройства и тома.
- Одинаковые имена или размеры не доказывают копию; равенство содержимого — только
  полный SHA-256. Хеш не подтверждает наличие резервной копии и исправность файла.
- Документы и прочие материалы в папке поездки/события остаются с ней, включая
  подпапки. Несвязанные файлы — в `НЕ ФОТО и НЕ ВИДЕО\HDDxx\исходный путь` для разбора.
  Неоднозначное остаётся на месте до просмотра плана.
- Удаление — только отдельной операцией по проверенному плану, после свежей проверки
  двух сохраняемых экземпляров на разных физических дисках.
